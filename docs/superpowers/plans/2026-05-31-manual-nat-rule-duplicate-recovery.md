# Manual NAT Rule Duplicate-by-Index Recovery — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Patch 11 — when FMC rejects an `fmc_ftd_manual_nat_rule` POST with a content-level "Duplicate entry … at rule index [N]" 400 error, the provider fetches the existing rule, verifies the content matches strictly via `reflect.DeepEqual`, and imports it instead of failing.

**Architecture:** A new generic helper `helpers.FindDuplicateByIndex` parses the error regex and fetches the existing rule by `?offset=N&limit=1`. The standard resource template's existing "fail" branch is modified to call the helper, parse the result via the resource's `fromBody`, and `DeepEqual`-compare against a copy of the plan (with `Id` rewritten). On match → import existing ID; on mismatch → surface error.

**Tech Stack:** Go 1.25, Terraform Plugin Framework v1.18, go-fmc v0.3.1, tidwall/gjson + sjson, bash + curl for integration tests.

**Spec:** [docs/superpowers/specs/2026-05-31-manual-nat-rule-duplicate-recovery-design.md](../specs/2026-05-31-manual-nat-rule-duplicate-recovery-design.md)

```go
// Copyright © 2023 Cisco Systems, Inc. and its affiliates.
// SPDX-License-Identifier: MPL-2.0

package helpers

import (
	"context"
	"fmt"
	"regexp"
	"strconv"

	fmc "github.com/netascode/go-fmc"
	"github.com/tidwall/gjson"
)

// dupIndexRegex matches FMC's content-level "duplicate at index" error. The
// pattern is anchored on both "Duplicate entry" and "rule index [N]" so it
// does not false-positive on unrelated messages that happen to mention an
// index.
var dupIndexRegex = regexp.MustCompile(`Duplicate entry .* at rule index \[(\d+)\]`)

// extractDuplicateIndex scans an FMC error and response body for the
// "Duplicate entry … at rule index [N]" pattern and returns N together with
// a bool indicating whether the pattern matched.
//
// Both the err string and the res string are scanned because FMC sometimes
// nests the descriptive text in either place.
func extractDuplicateIndex(err error, res gjson.Result) (int, bool) {
	if err == nil {
		return 0, false
	}
	candidates := []string{err.Error(), res.String()}
	for _, s := range candidates {
		if m := dupIndexRegex.FindStringSubmatch(s); m != nil {
			idx, perr := strconv.Atoi(m[1])
			if perr != nil {
				continue
			}
			return idx, true
		}
	}
	return 0, false
}

// FindDuplicateByIndex inspects an FMC POST error. If the error body matches
// FMC's "duplicate at index" pattern (currently emitted only for
// fmc_ftd_manual_nat_rule), it extracts the existing object's index, GETs the
// collection at that index, and returns the existing object's JSON.
//
// Returns:
//   - (foundRes, nil) when the pattern matched and the GET succeeded.
//     foundRes is items[0] of the response (a single rule).
//   - (gjson.Result{}, postErr) when the pattern did NOT match. Caller
//     proceeds with the original fail behavior.
//   - (gjson.Result{}, wrappedErr) when the pattern matched but the GET or
//     parsing failed.
func FindDuplicateByIndex(
	ctx context.Context,
	client *fmc.Client,
	resourcePath string,
	postErr error,
	postRes gjson.Result,
	reqMods ...func(*fmc.Req),
) (gjson.Result, error) {
	idx, ok := extractDuplicateIndex(postErr, postRes)
	if !ok {
		return gjson.Result{}, postErr
	}
	listURL := resourcePath + fmt.Sprintf("?expanded=true&offset=%d&limit=1", idx)
	listRes, err := client.Get(listURL, reqMods...)
	if err != nil {
		return gjson.Result{}, fmt.Errorf("duplicate at index %d but GET failed: %w (original POST error: %v)", idx, err, postErr)
	}
	item := listRes.Get("items.0")
	if !item.Exists() {
		return gjson.Result{}, fmt.Errorf("duplicate at index %d but no item returned from GET; original POST error: %w", idx, postErr)
	}
	return item, nil
}
```

### Problem

`fmc_ftd_manual_nat_rule` POST can fail with HTTP 400 and a body containing
`"Duplicate entry of ManualNatRule at rule index (N) is also present at rule index [M]"`.
This is FMC's content-level duplicate detection: the proposed rule has the
same NAT tuple as the rule already at index M. Manual NAT rules have **no
`name` field**, so the existing `IngestOnConflict` (which searches by a name
attribute) cannot recover.

Typical triggers: prior partial apply, rule pre-existing in FMC GUI, or two
`for_each` keys producing identical content (genuine HCL bug — see "Strict
comparison" below).

### Solution

Three pieces:

**1) New helper** — `internal/provider/helpers/dup_recovery.go`

```go
func FindDuplicateByIndex(
    ctx context.Context,
    client *fmc.Client,
    resourcePath string,
    postErr error,
    postRes gjson.Result,
    reqMods ...func(*fmc.Req),
) (gjson.Result, error)
```

Parses the regex `Duplicate entry .* at rule index \[(\d+)\]` against both
`postErr.Error()` and `postRes.String()`. If no match, returns
`(empty, postErr)` (caller fails as before). On match, GETs
`<resourcePath>?expanded=true&offset=N&limit=1` and returns `items.0`.

**2) Template change** — `gen/templates/resource.go` (around line 702)

The existing `{{- else}}` "fail" branch (used by resources without
`data_source_query`) is modified to first call `FindDuplicateByIndex`. On
match, the existing object is parsed via the resource's `fromBody`, compared
against the plan via `reflect.DeepEqual` (with `Id` rewritten on a plan copy
so the unset-vs-set ID difference is neutralized), and either imported or
the original error is surfaced.

Replace:
```go
{{- else}}
if err != nil {
    resp.Diagnostics.AddError("Client Error", fmt.Sprintf("Failed to configure object (POST/PUT), got error: %s, %s", err, res.String()))
    return
}
plan.Id = types.StringValue(res.Get("id").String())
plan.fromBodyUnknowns(ctx, res)
{{- end}}
```

with:
```go
{{- else}}
if err != nil {
    foundRes, dupErr := helpers.FindDuplicateByIndex(ctx, r.client, plan.getPath(), err, res, reqMods...)
    if dupErr != nil {
        resp.Diagnostics.AddError("Client Error", fmt.Sprintf("Failed to configure object (POST/PUT), got error: %s, %s", dupErr, res.String()))
        return
    }
    var existing {{camelCase .Name}}
    existing.fromBody(ctx, foundRes)
    planCopy := plan
    planCopy.Id = existing.Id
    if !reflect.DeepEqual(planCopy, existing) {
        resp.Diagnostics.AddError("Client Error", fmt.Sprintf("FMC reported a duplicate object, but the existing object's content differs from the proposed body. Original error: %s", err))
        return
    }
    res = foundRes
}
plan.Id = types.StringValue(res.Get("id").String())
plan.fromBodyUnknowns(ctx, res)
{{- end}}
```

The `{{- if and (not .PutCreate) (hasDataSourceQuery .Attributes)}}` branch
above (Patch 1's `IngestOnConflict`) is untouched.

`reflect` is auto-imported by `goimports -w internal/provider/` which is part
of `go generate` already.

**3) Integration test** — `tests/idempotency/` Test 8

Pre-creates an FTD NAT policy and a manual NAT rule via the FMC REST API
with content identical to the HCL. `terraform apply` then triggers the
duplicate error and `FindDuplicateByIndex` imports the existing rule.

### Strict comparison rationale

`reflect.DeepEqual` is used after setting `planCopy.Id = existing.Id`. Every
other model field (including `Domain`, all NAT-tuple fields) is compared
strictly. Mismatch → original FMC error surfaces, user resolves explicitly.
Two `for_each` HCL keys producing byte-identical content **will** both
import the same FMC ID; the resulting double-ownership becomes visible on
the next destroy/apply cycle. This is the deliberate fork philosophy:
opinionated provider, no opt-in flag.

### Affected resources

The template change affects every standard resource without
`data_source_query` (~277 resources). For all of them except
`fmc_ftd_manual_nat_rule`, the runtime behavior is unchanged because FMC
does not emit the "Duplicate entry … at rule index" pattern for those
resources — the helper returns the original error and the existing fail
path executes.
